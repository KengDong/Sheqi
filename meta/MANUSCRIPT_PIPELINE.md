>
> 原则：
> **设计、语言自然化、写作、编辑、盲读、总编裁决尽量分开。**

# 0A. 窗口 Handoff Gate

所有长期窗口每完成一个任务，必须执行：

> 任务产物 -> 更新 `handoffs/<role>/CURRENT.md` -> 新增 `handoffs/<role>/history/...` -> 再关闭Issue/切换任务。

正式规则：
> `meta/HANDOFF_PROTOCOL.md`

没有 handoff：
> **任务不视为完整交付。**

总评审改变项目阶段时，必须检查其它窗口CURRENT是否已经过期。

# 2. 第一章正式生产流水线

## Gate 0｜Reader-Language
必须完成：
- #24总审；
- Ch1 Reader-Language Sheet冻结；
- 所有 PROPOSE-RENAME 项完成作者拍板。

没过：
> 不进入Scene Spine。

## Gate 1｜Visual Support
第一章需要的内部视觉信息至少知道：
- 驿货行工作区大致动线；
- 常用工具 / 器物形态；
- 夜班吃食位置；
- 普通材质与阶层感。

不要求：
> 正式插图。

## Gate 2｜Scene Spine
Writer GPT只做：
- 连续时间线；
- 空间；
- 局部欲望；
- 阻力；
- 动作；
- 章尾状态；
- 幽默档位；
- Reader-Language约束。

不写完整正文。

总编审核一次。

## Gate 3｜Draft V0
Writer GPT：
> 按场景级写作。

不一键生成十章。

第一章先完整做完闭环。

## Gate 4｜Prose Edit
Prose GPT独立审核。

优先：
1. 工程 / AI语言；
2. 人物自然度；
3. 术语；
4. 对话；
5. 幽默；
6. 场景接缝。

## Gate 5｜总编合稿
只接受：
- 必要修改；
- 有证据的修改。

不因编辑个人偏好把全文重写成另一种腔。

## Gate 6｜Fresh Text Blind Read
新窗口。

不看：
- 章卡；
- 设计理由；
- Prose Bible；
- Reader-Language Map。

只看：
> 第一章正文。

## Gate 7｜作者确认
作者重点判断：
- 我自己愿不愿意看；
- 哪些地方别扭；
- 有没有AI味；
- 有没有具体画面；
- 陆野是否成立；
- 笑点是否自然。

只有作者确认：
> 才把第一章升级成 manuscript candidate。

# 3. 为什么不直接并行写第2—10章

第一章会验证：
- 语言；
- 人物；
- 幽默；
- 术语；
- 场景密度；
- 叙事距离；
- AI味。

如果第一章仍有系统性问题，
提前写2—10章只会成倍制造返工。

所以：

> **先把第一章当“生产线验收件”。**

第一章通过后：
- 第2—3章可以成组推进；
- 第1—3章再做一次文本盲读；
- 之后才进入第4—10章。

---

# 4. 第4—10章结构风险何时回看

Benchmark目前记录：
- 职业恢复链偏单一；
- 神秘线预算偏弱；
- 许可阶梯感。

当前：
> 不立即改。

回看点：

### 第一次
第1—3章真实正文完成后：
> 判断结构摘要是不是放大了机械感。

### 第二次
准备写第4章前：
> 重新审第4—10章Scene Spine是否仍只有“获得下一许可”。

### 第三次
第4—6章真实正文后：
> 若连续文本仍明显平，再做最小结构PATCH。

禁止：
> 现在为了治摘要平，提前加第二场事故或第二次怪味。

# 5. 新窗口策略

现在不再新开窗口。

当前已有角色足够。

只有一种情况再新开：

> **正式第一章正文完成，启动文本盲读。**

这时必须新开干净窗口。

后续若要做真人读者测试：
> 优先真人，而不是无限增加GPT数量。
