# READER LANGUAGE GATE｜读者语言与自然化闸门 V1

> 目的：
>
> **阻止作者工程语言、章卡占位词、制度数据库字段和AI名词堆直接泄漏进正式正文。**
>
> 本文件不改剧情，不改Canon。
>
> 它只回答：
>
> **作者知道这是什么 ≠ 人物会这么叫 ≠ 读者第一次应该这样认识。**

---

# 0. 最高原则

正式正文必须区分四层语言：

1. **作者工程语言**：只供研发、章卡、QA；
2. **世界正式语言**：制度、公文、专业人员可能使用；
3. **行业 / 人物口语**：现场人真正会说；
4. **读者首次体验语言**：第一次出现时最容易理解、最具体的呈现。

禁止把第1层直接复制成第4层。

---

# 1. 五类词汇分级

## A｜作者工程词｜正文默认禁止

典型：
- 正常安全包络
- 单一几何因果
- 稳定离体操作权限
- 续我承接负担
- 低风险受监督路径
- 社会位置变化
- 功能节点
- 信息预算
- 现实状态变化
- 生产价值
- 章尾推动力

规则：

> **只能指导写作，不能被人物或旁白直接说出来。**

如果正文出现这类抽象名词串，优先改成：
- 谁动了；
- 什么坏了；
- 人站哪；
- 钱少了多少；
- 谁不让谁做；
- 哪个动作来不及。

---

## B｜实现占位词｜写正文前必须具体化

典型：
- 货签夹
- 便宜热汤
- 长型重载转运架
- 封存退件
- 普通机械控制点
- 普通周转器具
- 关键承载位置上的廉价损伤件
- 手艺小单
- 稳定药
- 普通运输难点

这些词通常只描述“它在结构里起什么作用”，还不是活在世界里的东西。

规则：

> 写到该章前必须回答：
> - 它具体是什么？
> - 什么材质？
> - 人怎么拿 / 喝 / 推 / 修？
> - 现场的人平时怎么简称它？

禁止把“功能描述”直接当物件名。

---

## C｜Canon正式术语｜保留，但必须自然引入

来自 `canon/11_glossary.md` 的核心术语，例如：
- 修积
- 明悟
- 续我
- 舍破
- 舍备
- 舍契
- 漏舍
- 缺位
- 余痕
- 余灾
- 余器

规则：

> **概念先懂，术语后落。**

第一次出现时优先：
1. 动作 / 后果；
2. 人物口语；
3. 正式名词。

例：

不优先：
> “你的味觉舍备仍然有效。”

优先逻辑：
> “你舍味那份还在？”
>
> 读者先明白“有一份必要时舍掉味觉的应急准备”，后面再知道正式叫“舍备”。

Canon锁的是概念与正式词，不代表每个人每次都讲完整术语。

---

## D｜开篇实现 / 行业术语｜允许重新审名

例如：
- 修籍
- 押货候选
- 封位外环
- 封余工具
- 受监督额外手
- 低风险线

这类词未必属于Bible核心术语。

规则：

> 若普通表达足够完成叙事，不为了“世界观感”强造词。

必须经过三问：
1. 这个词是否会重复使用至少多次？
2. 现场人物是否真的需要这个统一称呼？
3. 这个词是否比普通说法更省认知，而不是更费认知？

若三问不能成立：
> 降级为普通描述或只留公文层。

---

## E｜普通物件 / 普通生活｜优先使用现实可感语言

原则：

> 普通世界占九成，才会让异常的一成显得异常。

不要为：
- 汤
- 夹子
- 绳扣
- 桌子
- 空架
- 旧零件
- 药
都造“仙侠专名”。

---

# 2. 普通物件命名规则

## 2.1 能描述，就先别命名

第一次：

> “一只夹货牌的旧木夹”

后面：

> “木夹”

通常优于：

> “货签夹”。

## 2.2 功能名不等于生活名

章卡写：
> 便宜热汤

正文必须具体到：
> 某一种真的能端上桌的汤 / 羹 / 粥 / 面汤。

章卡写：
> 普通周转器具

正文必须知道：
> 到底是空返架、木箱、绳盘、托架还是其它具体物。

## 2.3 不为一次性物件造专名

若一个东西：
- 只出现一次；
- 不承担制度含义；
- 不会成为长期资产；

优先普通描述。

---

# 3. “正式语 / 行话 / 口语”三层表

任何重要制度词在进入正文前，最好至少知道：

| 层级 | 用途 |
|---|---|
| 正式语 | 公文、记录、专业解释 |
| 行话 | 货行 / 舍务人员工作中常说 |
| 日常口语 | 陆野、乔九等熟人怎么说 |

正文不要求三种都出现。

但作者必须知道：
> 为什么这个人在这个场景会选这一种说法。

---

# 4. 第一次出现规则

## 4.1 一句话里不要靠两个陌生造词才能读懂

若一句话的核心因果必须先懂两个以上新专名，视为高风险。

优先拆成：
> 动作 -> 后果 -> 名字。

## 4.2 新词必须挂在当前欲望上

读者记“舍备”，不是因为词典解释，
而是因为：
> 陆野今晚可能真要拿它救命。

## 4.3 不要求第一次就知道精确定义

第一次只要能答：
> 大概是什么？
> 现在为什么重要？

后续再精确。

---

# 5. 事故自然化规则

事故章禁止直接使用“工程报告语法”。

## 禁止倾向
- 长型重载转运架的一侧导向轮脱槽；
- 越出正常安全包络；
- 侵入凹入式应急服务位；
- 稳定持续操作辅助制动/牵引结构。

## 正文应优先回答
1. **先听到 / 看到什么？**
2. **哪一头突然往哪甩？**
3. **谁来不及躲？**
4. **什么东西被擦裂 / 顶住？**
5. **陆野站在哪，手够不到哪里？**
6. **筑基以后多出来的那个动作，读者肉眼怎么理解？**

原则：

> **空间因果必须精确；语言不必像事故鉴定书。**

作者可以看图。
读者应该看见动作。

---

# 6. 机制体验优先于机制命名

例如：

内部机制：
> 舍契切离味觉，降低本次续我负担。

正文体验顺序应优先：
1. 陆野做出决定；
2. 舍契真正执行；
3. 味觉这一部分从他的当前主体里被切走；
4. 原本卡住的续关出现变化；
5. 筑基成立；
6. 之后才允许补最少必要术语。

禁止把高潮写成：
> “舍契执行成功，续我承接负担下降，筑基完成。”

---

# 7. AI机械感高风险句法

出现以下模式时必须警惕：

## 7.1 名词叠名词
例如：
> “低风险受监督新筑基操作适应路径”

优先拆成人话。

## 7.2 斜杠并列
例如：
> “辅助制动 / 牵引结构”

正式正文只能选一个具体东西。

## 7.3 过度限定
例如：
> “当前这一次、这套功法、这个续关状态”

作者必须知道这些限定。
人物第一次不必一口说完。

## 7.4 抽象动作
例如：
- 建立路径
- 完成适应
- 产生价值
- 改变边界
- 进入状态

正文优先换成可看见的动作和后果。

## 7.5 防误读声明
例如：
- 这不是训练
- 这不是正式资格恢复
- 本章不出现异常味

这些是章卡语言。

正文里不能让旁白替作者做免责声明。

---

# 8. 具体性闸门

每个正文场景开写前至少检查：

- 吃的具体是什么？
- 喝的具体是什么？
- 手里拿的是什么？
- 这个东西多大 / 多重 / 什么材质？
- 人怎么叫它？
- 地面 / 光 / 气味 / 声音里至少哪个会影响动作？
- 钱 / 工时 / 距离是否能用人物直觉感受到？
- 是否存在“普通人从没见过但作者给它一个抽象功能名”的物件？

若答案长期只有：
> “某种、普通、低风险、便宜、常用”

说明还停留在章卡层。

---

# 9. 术语认知预算

不设机械“每章最多X个新词”KPI。

但使用两个硬警报：

### 警报A
> 同一句核心因果依赖两个以上未解释专名。

### 警报B
> 同一小场景连续出现三个以上读者第一次见的新造词。

触发后必须检查：
- 是否能用普通描述替一个；
- 是否能晚一个；
- 是否其实是作者工程词。

---

# 10. 角色语言测试

每个专业词问：

> **这个人真会这么说吗？**

乔九可能说：
> “舍味那份还在？”

不会总说：
> “你的味觉舍备有效性仍符合当前续关适配条件。”

周照比乔九更正式，
但也不等于公文机器。

现场工人优先：
> 短、快、能执行。

# 11. 第一章—第三章当前已标红项目

| 当前工程 / 占位表达 | 分类 | 正文处理方向 |
|---|---|---|
| 货签夹 | B | 先写“夹货牌的旧木夹”等具体物，再简称 |
| 修籍 | D | 重新审是否需要高频专名；优先普通“修行凭证/记录”功能 |
| 味觉舍备 | C+D | 正式概念保留，人物口语先行 |
| 便宜热汤 | B | 正文前必须选具体食物 |
| 长型重载转运架 | B | 正文前定具体形态与现场短称 |
| 导向轮脱槽 | B/D | 可以是事故事实，但优先用动作呈现 |
| 封存退件 | B/D | 先具体成“正要退回舍务处的某只封匣/封件” |
| 正常安全包络 | A | 禁止进正文 |
| 凹入式应急舍台服务位 | A+B | 只保留“墙边内凹的应急舍台”等可见形态 |
| 封位外环 | D | 审是否简化为“封环/外环”等现场词 |
| 核心 | A/D | 不在正文抽象叫“核心”，具体写设备部位 |
| 辅助制动 / 牵引结构 | A+B | 正文前必须选定一种具体机构 |
| 续我承接负担 | A | 作者侧概念，正文默认禁用 |
| 舍契切离味觉 | C+A | 先写执行体验，再落术语 |
| 低阶可控范围 | A | 禁止作为叙述结论 |
| 稳定药 | B | 正文前选具体药物形态 / 用途称呼 |
| 受监督额外手 | D | 审现场是否有更自然短称 |
| 低风险受监督班表 | A+D | 正文用“接下来几天都有班，但只能跟着某人做某类活”等现实表达 |

# 12. 正文前新增必做资产

每章正式初稿前先做：

> **Reader-Language Sheet**

至少包括：

1. 本章新增专名；
2. 本章占位物件；
3. 正式语 / 行话 / 口语；
4. 第一次出现方式；
5. 本章必须具体化的食物 / 工具 / 设备；
6. 禁止直接进入正文的作者工程词；
7. 需要通过动作让读者理解、但暂不解释定义的机制；
8. 可能产生“AI机械感”的句法。

没有这张表：
> 不开正式草稿。

---

# 13. 变更边界

本闸门允许：
- 改章卡中的实现名；
- 改普通物件；
- 改口语；
- 延后术语；
- 降级不必要专名。

本闸门不得自行：
- 修改Bible底层概念；
- 改舍弃规则；
- 改事故因果；
- 改人物核心动机；
- 改章尾状态。

若发现核心术语本身真的不自然：
> 走单独 Proposal，不静默改Canon。
