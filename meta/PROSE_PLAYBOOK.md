# 2. 写作AI输入最小包

只给当前场景必要信息。

## 权威
- 相关 chapter card 片段；
- 必要 Canon；
- 当前人物状态。

## 声线
- 当前幽默档位；
- 叙事距离；
- 旁白禁区。

## 人物
- 当前在场；
- 本场注意力优先级；
- 本场禁止触发的固定梗。

## 禁止
- 不新增人物；
- 不新增规则；
- 不提前解释；
- 不写主题总结。

---

# 3. Prose Editor 输入

必须给：
1. 草稿；
2. `meta/PROSE_BIBLE.md`；
3. 当前场景 / 章卡结果状态；
4. 人物当前关系；
5. 当前幽默档位；
6. 必要 Canon 边界。

尽量不给：
- 作者想表达的哲学；
- 想让读者“笑/哭”的目标；
- 研究来源作品。

# 4. Prose Editor 检查清单

## A｜AI味
1. 是否解释刚刚已经看懂的动作？
2. 是否连续两次换说法解释同一情绪？
3. 是否每段都想漂亮收尾？
4. 是否频繁出现三连句式？
5. 是否每场都有“他意识到/他明白/这意味着”？
6. 是否过度使用“微微一愣、心中一动、眸光一凝”类万能反应？
7. 是否所有场景都结构完整得像模板？
8. 是否每章都强反转？

## B｜旁白
9. 旁白是否比人物更机灵？
10. 是否出现现代互联网吐槽感？
11. 是否替读者说“这很荒诞”？
12. 是否替人物解释主题？
13. 是否在重场找漂亮比喻盖过事实？

## C｜对白
14. 是否所有人都说完整句？
15. 是否所有人都太会表达自己？
16. 是否一轮争论只是重复立场？
17. 遮掉名字后，人物对白是否全部可互换？
18. 是否有人突然为了包袱降智？
19. 是否配角只负责递信息 / 递任务？

## D｜信息
20. 是否一次讲完太多设定？
21. 新术语是否先讲名字、后讲作用？
22. 是否为了读者解释而让角色说自己本来就知道的事实？
23. 是否在章卡没要求时新增神秘线索？
24. 是否把局部制度写成全国规则？
25. 是否把作者工程词直接复制进正文？
26. 是否把“普通/便宜/低风险/常用”当成了物件本身？
27. 是否一件一次性普通东西也被强行命名？
28. 是否一句话同时依赖两个以上读者第一次见的新专名？
29. 是否出现斜杠候选、三层以上名词串或公文式限定？
30. 现场人物是否说了现实中不会在紧急时完整说出的制度句？

## E｜幽默
25. 是否出现“作者觉得这一页应该再来个笑点”的痕迹？
26. 旁白是否接了人物第二层梗？
27. 一次小笑点是否被发展成完整相声？
28. 重场是否在后果落地后立刻补偿性开玩笑？

## F｜场景真实感
29. 是否只有“有用动作”，没有一点真实但不解释主题的小动作？
30. 空间是否能看清？
31. 工具 / 器物是否真的影响动作？
32. 人物是否一直站着说话？
33. 工作场是否像说明书，不像人在干活？

## G｜接缝
34. 新场景是否重新解释刚发生的事？
35. 是否每场都重新写一次“他今天的目标是……”？
36. 是否人物每次出现都重新介绍？
37. 过渡是否像“接下来来到另一个模块”？
38. 本章读完是否像几段合格短篇拼接？

# 5. 声线故障排查

## 5.1 太冷
症状：
- 陆野不说话；
- 日常没有人物错位；
- 第一章像职业纪实。

修法：
- 不加旁白笑话；
- 只增加人物的一次短反应；
- 从熟人 / 小损耗场下手。

## 5.2 太闹
症状：
- 每页都有人接梗；
- 乔九、石小庚、陆野都变聪明话王；
- 旁白也在吐槽。

修法：
- 删第二个包袱；
- 让人物回到当前工作目标；
- 降旁白存在。

## 5.3 太“主题”
症状：
- 人物主动总结“舍/留”；
- 生活锚点像人生导师；
- 罗槐像“舍弃派”。

修法：
- 只保留动作；
- 删除解释动作意义的下一句。

## 5.4 太AI
症状：
- 每场完整；
- 每段漂亮；
- 每个人都准确；
- 章尾必金句。

修法：
- 保留一点没有被总结的动作；
- 打断完整对白；
- 允许普通通知 / 决定做章尾；
- 删除重复解释。

# 6. 三微场景基准

## 坏货签夹
目标：
> A-lite。

机制：
> 动作先成立 -> 一句轻反应 -> 不追第二个包袱。

## 咸汤
目标：
> A-lite。

机制：
> 生活动作 -> 乔九轻碰一次 -> 结束。

## 苦药
目标：
> A / 收声。

机制：
> 身体事实先成立，意义后置。

禁止把 calibration 文本自动复制进 manuscript。

# 7. 章尾替代库

可用：
- 名字被写回班表；
- 某人给出一个有限允许；
- 主角作出明天要做的决定；
- 某个现实条件发生变化；
- 当前动作尚未完成；
- 钱到账；
- 任务真正开始。

慎用：
- 突然黑影；
- “他不知道的是”；
- 每章神秘味道；
- 每章隐藏大人物；
- 强行一句哲理。

---

# 8. 正文阶段工作原则

- 场景工作区间可常用600—1500字，但不硬凑；
- 200字够就停；
- 1700字自然需要也允许；
- 关键是一个主要空间 / 一个局部目标 / 一次主要状态变化；
- 复杂事故可以拆成连续微段，但仍属于同一主场景。

---

# 9. 作者审核模板

作者不必逐字重写。

重点问：

1. 第一段我愿不愿意继续读？
2. 陆野像不像一个真实的人？
3. 我笑的地方是不是人物自然造成的？
4. 有没有“作者在教我理解主题”的感觉？
5. 乔九 / 石小庚等人对白能不能互换？
6. 重场是不是在装文学？
7. 章尾是不是为了追读硬拧？
8. 有没有一句明显“AI太会写”的句子？
9. 有没有一段我会下意识跳过去？
10. 这章最想留下的一个画面是什么？

---

# 10. 变更规则

Prose Bible 只在以下情况升级版本：
- 多章正文反复暴露同一声线故障；
- 角色长期漂移；
- 盲读反馈稳定指向同一问题；
- 正式 manuscript 形成了比规则更高质量、更稳定的实践。

不能因为单章某个笑话成功就新增“以后都这么写”的规则。
