# HEAD-TIER COMMERCIAL FICTION OS V2

# 0. North Star

> **让陌生读者愿意点开、前3章不退、第一轮高潮后更想追、20/50/100/300章持续拿到更大的果实，并让Premium随规模上升反而更重要。**

不优化“端正感”。
不优化“架构文档完整度”。
不优化“像某本名作”。

只优化：
> click -> stay -> care -> gain -> expand -> compound -> keep reading/pay.

# 1. Three-Engine Standard

任何重点候选必须同时具备三种发动机：

## Engine A｜Cold-Start Engine
解决：
> 没名气，为什么看Ch2/Ch3？

可由以下一种或组合承担：
- personality-comedy;
- personality-intensity;
- relationship chemistry;
- competence + attitude;
- spectacle/premise.

## Engine B｜Tangible Growth Engine
解决：
> 我追20/50/100章具体拿什么？

至少连接三种：
- power;
- money/resource;
- status;
- relationship/team;
- asset/territory;
- access;
- knowledge;
- organization/life state.

## Engine C｜Long-Run Expansion Engine
解决：
> 为什么300章不是Opening重复300次？

要求：
- old-state compounding;
- social-system expansion;
- mode rotation;
- antagonist adaptation;
- recontextualization;
- durable recurring cast.

缺一个都不是头部准备状态。

# 2. Unknown-Author Cold-Start Requirements

## First 500 words
至少给出一种：
- impossible thing in motion;
- protagonist signature behavior;
- strong danger;
- social reversal.

禁止连续解释世界规则才开始故事。

## First ~2k
Reader应知道：
- 主角眼前想要什么；
- 他和普通“聪明男主”有什么不同；
- 书的语气是什么；
- 第一个爽/险/反差兑现在哪里。

## First ~5k
至少留下：
- 一个永久果实或永久代价；
- 一个值得再见的固定人物；
- 一个只有本书才成立的场面。

## First ~10k
必须开始暴露：
- Book Contract;
- tangible next rung;
- larger-world shadow;
- Concept第二次不同用法。

# 3. Protagonist Non-Replaceability

前3章后，必须能在不提外挂/Premium情况下描述主角。

主角至少拥有：
1. concrete desire;
2. behavioral bias;
3. flaw/oddity;
4. social style;
5. repeatable scene-generation source.

“聪明、冷静、靠谱”不够。

更强的是：
> 会把所有人情算账，但欠人的账一定还；
> 疼得要死还会和医生抬杠；
> 极度厌恶浪费时间；
> 能丢面子但不能丢某条私人规则。

这些人格必须影响剧情结果。

# 4. Humor / Mania Is a Full Route

不默认 serious > funny。

如果发癫搞笑版：
- 更想追；
- 主角更好记；
- 关系更有戏；
- 仍保住真后果；
- 长线可复利；

则可以优先。

可持续喜剧来源：
- stable worldview conflict;
- role/status mismatch;
- recurring relationship;
- absurd but rational institution;
- protagonist habit with real consequences.

禁止：
- 随机网络梗；
- 全员同声；
- 笑话取消死亡/损失；
- 主角为搞笑突然变蠢；
- 一招梗吃100章。

理想：
> **人可以很疯，世界必须认真。**

# 5. Book Contract

Opening结束前，Reader应能回答：

1. 这本书长期反复爽在哪？
2. 主角在积累什么？
3. 下一步具体去哪/做什么？
4. Ch20–100有什么看得见的梯子？
5. 更大的世界刚露出了哪一层？
6. 哪些人会回来？
7. 第一轮得到的东西以后为什么还会升值？

如果只剩：
> “我想知道谜底。”

则Book Contract不足。

# 6. Near / Mid / Far Horizon

## Near
1–3章内具体问题。

## Mid
10–30章可用一句话等待的成果：
- 资格；
- 第一次真正突破；
- 第一次正式任务；
- 第二次副本；
- 一笔钱；
- 一个职位；
- 一个队伍。

## Far
100章+可感知规模：
- 新修行体系；
- 区域产业；
- 多幸存者改写现实；
- 家族/组织跨代扩张。

Far只能露影，不要讲义。

# 7. Opening Arc Requirements

完整Opening Arc必须同时证明：

1. Premise兑现不止一次；
2. 主角有性格；
3. 至少一个非主角可追；
4. 第一个真实果实；
5. 第一个真实成本；
6. 世界不是只围绕这件事；
7. 第一轮高潮成立；
8. 高潮后Reader欲望上升。

# 8. Climax Handoff

每个Major/Medium payoff结尾至少交出2项：

- named next target;
- persistent asset;
- visible ladder;
- larger social layer;
- irreversible cost;
- new exclusive choice.

至少1项必须可命名/可计数/可定位：
- “七天后资格考”
- “十二天后第二次进入”
- “正式观察员证”
- “第一条稳定劫痕循环”
- “另一个城市出现陌生规则”

禁止只有：
> “真正的秘密才刚开始。”

# 9. Multi-System Scene Rule

头部大书的“大”来自：
> 一个普通事件能同时推动多个系统。

高价值场景通常移动2–5项：
- immediate goal;
- resource;
- power;
- status;
- relationship;
- world implication;
- future option.

这不是Checklist。
而是检查世界是否真的互联。

如果大量场景只移动一个局部指标：
> 容易小家子气。

# 10. Universal Conversion Layer

长篇最好有1–2种Reader秒懂的转换桥。

例如：
> money -> cultivation -> rank -> opportunity.
> score -> reward -> access.
> qualification -> job -> resource -> power.
> public rule -> social adaptation -> market/status.

禁止十种彼此无关的货币/等级。

# 11. Tangible Growth / Reward Rotation

每20–50章应留下多种永久状态。

轮换奖励：
- power/combat;
- money/resource;
- status/credential;
- relationship;
- access;
- information;
- organization/territory;
- world-state.

不能每轮只发：
> 新线索
或
> 新技能。

# 12. Ch20 / 50 / 100 / 300 Gate

## Ch20
至少3个不同维度发生永久变化。

## Ch50
至少一个Ch10旧人物/资产/规则在新场景中产生意外价值或代价。

## Ch100
进入更大的SOCIAL SYSTEM，不只是更远地图/更强怪。

## Ch300
至少两次真正换故事模式。
原Premium仍是核心。

# 13. Mode Rotation

允许的模式变化示例：
- survival -> preparation;
- worker/job -> competition;
- investigation -> cultivation creation;
- individual -> team;
- household -> public system;
- local market -> regional industry;
- dungeon -> reality conflict.

模式变化必须由旧状态推动，而不是“作者腻了所以换地图”。

# 14. Character / Relationship Engine

前30章：
- 2–4个非主角产生明确Reader情绪；
- 每个人有自己的欲望；
- 主角不在场也会行动；
- 关系会记旧账；
- 升级会改变别人对主角的行为。

至少一个固定关系应本身可生成场景。

# 15. Antagonist Adaptation

对手不能永远不知道Premium。

阶段要求：
1. opponent encounters effect;
2. opponent forms model;
3. opponent exploits cost/constraint;
4. protagonist must change behavior;
5. conflict moves to larger layer.

如果主角机制只虐不会学习的人：
> 长线爽感会空。

# 16. Mystery / Recontextualization

谜团不是“藏答案”。

好谜底必须：
- 改变旧信息价值；
- 改变人物关系；
- 改变可以做的事；
- 打开更大的实际目标。

禁止：
> 答案 = 更大的组织/更古老的阴谋。

# 17. Case-Supply Stress

重点候选必须过：

> **一段长时间不发新核心Case，书还能跑吗？**

具体：
- skill book: no new skill;
- scar book: no new scar;
- rule book: no new returned rule;
- customer book: no new customer;
- building book: no new building.

若不能：
> engine仍是Case supply.

# 18. Prose Naturalness

进入P7前必须做Reader-Friction Pass：

- first-use jargon;
- invented-noun density;
- nickname anchoring;
- place/number continuity;
- semantic half-beats;
- scene geography;
- dialogue orality;
- summary sentence overuse;
- AI-like “他忽然明白/这不是…而是…”整齐桥句。

原则：
> Premium负责陌生，表层语言尽量让Reader省脑。

# 19. Platform Split

## Qidian
更看重：
- 付费章节值；
- 永久资产；
- Ch20/50/100回报；
- 生活/关系/社会系统复利；
- 100万字以上可持续。

## Fanqie
更看重：
- 第一屏；
- 前3章；
- 一行Premise；
- 快结算；
- 人设/语气；
- 章尾连续读欲。

同一本书可调：
- 包装；
- 开头密度；
- 回报间隔。

不需要改Root Story。

# 20. Architecture vs Writer

## Architecture可以锁
- Book Contract;
- irreversible rules;
- Ch20/50/100/300状态；
- core cast desires;
- conversion layers;
- mode changes;
- kill conditions.

## Architecture不要锁
- 每章必须完成的指标；
- 每场戏台词；
- 所有笑点；
- 逐章700章施工表。

Writer只拿最小包：
1. desire thesis;
2. core rules;
3. 4–6 character desire cards;
4. irreversible ledger;
5. current Near/Mid/Far;
6. voice;
7. current scene pressure.

# 21. Behavioral Evidence Hierarchy

1. human target-reader voluntary behavior;
2. clean-room voluntary behavior;
3. continuous prose experience;
4. unprompted character/future desire;
5. reservoir;
6. external benchmark;
7. architecture;
8. selfcheck.

任何架构PASS不能覆盖：
> “真人就是不想看。”

# 22. Revise / Kill Conditions

## REVISION
- good pull but weak Book Contract;
- strong architecture but generic protagonist;
- strong first arc but poor Handoff;
- good engine but prose friction;
- promising mode rotation but one subsystem thin.

## ROOT SCALE FAILURE
- no-fresh-case stress fails structurally;
- Ch100 only means stronger enemy/bigger map;
- Premium becomes irrelevant at high scale;
- all non-MC are interfaces;
- repeated behavior failure at multiple prose gates;
- fixing requires changing Root Concept.

# 23. Post-Prose Reader Protocol

Reader first reads without rubric.

If genuine abandon:
> stop immediately.

After stop/finish record:
- exact point;
- last real interest;
- who they care about;
- what they expected next;
- whether payoff increased desire;
- one remembered scene;
- one remembered person;
- perceived size of future book;
- prose friction.

# 24. Final Gate Sentence

> **入口要狠，主角要有味道，世界要互联，高潮要交接，果实要落账，旧东西要复利，故事模式要换挡。**
