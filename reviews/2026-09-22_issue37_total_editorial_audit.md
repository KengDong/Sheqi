# 2. 三个必须修的硬问题

## HARD 1｜Secret Ladder S2 与后续“感知真、归因错”发生自我剧透

当前V2：

> S2已经明确告诉陆野：
> **尝到的位置不等于真正源头，载体可以带痕。**

而Payoff Ledger / 原主线又在Mid-Late安排：

> **感知是真的，但陆野把载体错判成当前货物源头，造成真实损失。**

这是重复，且前者会削弱后者。

如果陆野早就已经通过一次现实损失学会：
> “信号位置≠源头”，

那么后面再用同一错误做第一卷大错，会显得：
- 主角重复犯已学会的错；
- 或作者为了保留旧桥段让他降智。

### PATCH要求

秘密梯改序，不允许S2提前完整结算“载体≠源头”。

建议：

- S0：舍后仍需处理；
- S1：异常可重复，至少一部分来自外界；
- S2：异常之间存在稳定行为差异，但**来源仍不清楚**；
- S3：少数对象出现窄用途 -> 第一收藏；
- S4：官方/市场早已做部分分类；
- S5：**第一次大误判后**，才确认“信号位置≠源头 / 载体可带痕”，并形成接触链验证法；
- S6：共享物/地点可以积累；
- S7：部分残留受控利用 + 正规流程存在共同导走逻辑；
- S8：只种“导向哪里 / 利用与安全双重性”的种子。

允许细节微调，但必须保护：
> **第一卷大误判仍然是一次真正的新认知代价。**

## HARD 2｜“成熟社会为什么还有废料价捡漏？”目前没有回答

#37把资产发动机做得很完整：

> 废料价旧物 -> 陆野多验证一步 -> 窄用途 -> 变现。

但与此同时又设定：
- 官方早已分类；
- 正规市场存在；
- 合法利用存在；
- 有牌照/封存/交易要求。

于是一个普通读者很容易问：

> **既然这个文明已经围绕舍弃运行很多年，为什么真正有价值的异常物还会长期以废料价落到一个穷杂役手里？专业机构都在干什么？**

如果不回答，整个“捡漏/资产增长”会建立在：
> **全世界都比主角笨**
上。

这是当前#37最大的世界—爽点接口漏洞。

### PATCH要求：建立“低端市场失效模型”

不是新增Canon系统，只需给第一卷现实层一个可信模型。

至少回答：

1. **哪些东西正规体系一定不会漏出来？**
   - 高风险；
   - 高价值；
   - 已明确分类的受控残留。
   这些不能成为陆野早期捡漏池。

2. **哪些东西可能被低估？**
   推荐：
   - 低风险、低强度、混杂来源的旧件；
   - 分类成本高于单件预期价值的混批；
   - 普通器物被顺带沾染，尚不足以触发高等级监管；
   - 用途极窄、只在特定条件下成立，通用市场不愿为它支付检测成本。

3. **为什么陆野有边际优势？**
   不是更聪明，而是：
   > 尝余降低“从一堆低价值东西里挑出值得验证对象”的筛查成本，
   但仍不告诉他价值/用途/来源。

4. **为什么别人不复制？**
   - 单件收益低；
   - 验证费时；
   - 信号只有陆野当前这个特殊缺位后遗症能感到；
   - 真正高价值区仍被机构占据；
   - 他吃的是“没人愿意逐件检查的边角市场”，不是制度大漏洞。

5. **早期第一件收藏如何合法取得？**
   必须写清：
   - 是普通废件/可公开处理旧件；
   - 还是通过货主允许的低价处置；
   - 不能在知道受控残留后还靠“顺手捡走”推进。

只要这一模型不成立：
> Option A会退化成传统鉴宝捡漏逻辑，世界成熟度会崩。

## HARD 3｜A / C不应该继续原样交作者二选一

A的优点非常清楚：
- 前10章拿东西快；
- 主角主动；
- Money/Collection强；
- 新人作者的即时爽感强。

但风险也真实：
> 容易把《舍弃》重心改造成“修仙捡漏创业”。

C的优点：
- 职业/团队/修炼底盘稳；
- 原Concept与人物关系更完整；
- 后期余灾更自然。

但风险：
> 很容易以“均衡”为名，重新滑回许可恢复旧书。

因此总评审不准备把A/C原样扔给作者选。

### 总评审定向合并原则

下一版只做一个主Baseline：

> **C的骨架 + A的速度和资产兑现。**

也就是：

- **保留C：**
  - 驿货行作为BASE；
  - 团队/正常修炼持续占重要冲突；
  - 流程余灾终局；
  - 市场/资产不吞掉职业与人际。

- **采用A：**
  - 第一卷早段就出现普通修复Money；
  - 第一件异常物前移；
  - 第一收藏前10章附近落袋；
  - 资格线显著降级；
  - 主角主动花验证成本；
  - Ch1核心机制尽量直接兑现。

内部暂称：

> **AC-Hybrid｜职业底盘上的资产飞轮。**

这不是第四套大研究。
只做一次整合PATCH。

# 4. Payoff Ledger的过程修正

批准Ledger作为设计诊断工具。

但以下数字规则降级为：
> **RED FLAG / REVIEW TRIGGER**
而不是正文KPI：

- “8—12章至少2种Payoff”；
- “3—4小弧必须有一次物理资产”；
- “卷末必须精确回用3类资产”。

原因：
> #36刚刚建立“不把规则机械执行成AI模板”的教训。

真正Hard原则只有：

1. 不能长时间只有Status；
2. 主要弧结束要有可感知状态变化/存量；
3. Payoff要轮换；
4. 卷末前期积累必须有真正回报，不得全靠总结表。
