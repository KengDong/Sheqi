# 2026-09-27｜Ch1 V8 Author Rejection Notes

status: HARD AUTHOR FEEDBACK / NOT STABLE-PROSE-CANON YET

## Author rejection
V8仍然不可接受。

作者明确指出：

1. “这话说得很像一个花了钱的人。”
   - 属于旁白替读者总结；
   - 现场已经能证明的信息，作者又站出来解释一次；
   - 破坏沉浸。

2. “你负责出问题，我负责不让你藏。”
   - 像为“显得有趣”提前设计的台词；
   - 不像两个第一次见面的真人自然说话。

3. “嘴角动了一下，最后还是没笑出来。”
   - 无意义AI反应；
   - 没有真实情绪或关系变化支撑。

4. “阵法能拦伤，不负责替你们把气运回来。”
   - 为了写得聪明而写；
   - 不像教练自然口语；
   - 世界信息被做成金句。

5. 第三式 / 第四式依然太抽象。
   - 虽然术语由“转”改成“式”，但Reader仍没有动作图像；
   - 需要给第三式、第四式明确功能和身体结果；
   - 不能只靠编号。

6. 旁白总结依旧过多，用词机械。
   - “这才是买方 / 很合理 / 问题在于 / 这说明”等作者判断不应替现场说话。

## Root cause
此前虽诊断出“功能稿腔”，但V8落笔仍然是：
> 先列功能 -> 每个功能写一句证明 -> 再用旁白确认Reader理解。

这导致分析正确、正文失败。

## New drafting guard
下一版不得直接整章重写。

必须先：
1. 把《流云步》第三、第四式具体化；
2. 写一个局部场景样板；
3. 删除一切“解释上一句为什么成立”的旁白；
4. 对话只从说话人的当前欲望出发；
5. 作者确认样板的真人感后，才扩成整章。

## Hard negative examples
禁止再次出现同类句：
- “这话说得很像一个花了钱的人。”
- “这才是买方。”
- “很合理。”
- “问题在于……”
- “嘴角动了一下……”
- “像是……又不像……”作为无意义反应填充。

## Process correction
Draft order:
> 人在现场做事 -> consequences -> minimal interpretation.

NOT:
> 设定/功能说明 -> character line -> narrator explanation.
