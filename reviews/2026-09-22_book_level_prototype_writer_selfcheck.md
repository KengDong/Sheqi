# Book-Level Prototype Duel｜Writer Selfcheck

## 0. Scope

本自检只检查四篇匿名 Prototype 是否按同一 Writer 标准完成，以及是否满足 Brief G1—G10。

不排名，不判断赢家，不替 Blind Reader 做口味裁决。

## 1. Control Variable Check

- Prototype A：约 2069 字符
- Prototype B：约 2246 字符
- Prototype C：约 2484 字符
- Prototype D：约 2234 字符

四篇均落在 brief 要求的约 1800—2600 中文字符区间。

篇幅差异来自：
- A 主要是办公室人际与一次真实离职结算；
- B 包含一次成交前与成交后的时间跳切；
- C 含一个完整的危险现场空间与谈判回合，因此略长；
- D 含一个职业动作现场、现场议价与结算。

未给任何一篇额外第二反转、第二系统、第二能力或第二章级展开；没有用篇幅给某个候选偷加世界观优势。

## 3. Human-Prose Auxiliary Check

四篇均额外检查：
- 第一屏人物、地点、当前问题可复述；
- 当前因果依赖的新词都能用普通话还原；
- 高压动作场景 C / D 有稳定空间锚；
- 没有角色互相背制度全文；
- 没有系统面板式技能枚举；
- 同一规则未由对白、旁白、内心连续复读；
- 结尾停在已发生的新状态，不用作者总结“人生从此改变”。

## 4. 仍需 Blind Reader 重点观察的风险

### Prototype A
- 中段“死后劳务续行 / 抚恤扣除”仍带制度场景属性。
- 当前已把胜负放在陈默的真实选择而不是法条漏洞上；Blind Reader需判断公司会议段是否仍显流程味。

### Prototype B
- 第一屏必须直接讲清“卖明天”的交易结果，因此有一小段明确机制说明。
- 当前后半主动转向“我为什么卖得这么便宜 / 我要学会买”，用于避免醒来后退化为单纯失忆调查；Blind Reader需判断转向是否自然、是否过快。

### Prototype C
- 最大风险是把谈判直觉写成作者代替主角神算。
- 当前只让季川抓住一个人人看得懂的事实：危险者一直盯成交倒计时；后续手段也只做“一分钟换一步”。
- 许昭末段承担长期关系入口，需由 Blind Reader 判断她是否仍有“任务派发者”味道。

### Prototype D
- 接雷现场包含引雷桩、分劫绳、备用桩，存在工程细节变重风险。
- 当前每个物件只在改变生死动作时出现；核心胜利来自观察、同伴信任与现场议价，不来自主角天生抗雷。
- 个人劫只在最后推动下一步，未改变本次胜负；后续不得吞掉劫工职业人生。

## 5. Equal-Treatment Statement

Writer未依据总评审偏好调整：
- 文学化程度；
- 反转数量；
- 角色数量；
- 结算强度；
- 世界解释详细度；
- 章尾谜团强弱。

四篇都按“第一屏有事 -> 人物选择 -> Concept在事件里兑现 -> 至少一次真实结算 -> 长期关系/未来生活启动”的同一标准完成。

## 6. Writer Boundary

本轮到此停止。

不做：
- 自行排名；
- 宣布Prototype赢家；
- 写任何一篇第二章；
- 把任一Prototype升级为正式立项；
- 修改Canon / Outline；
- 回头继续旧Sheqi Formal Ch1。

下一步应由全新 clean-room Blind Reader 只读四篇匿名正文后判断。
