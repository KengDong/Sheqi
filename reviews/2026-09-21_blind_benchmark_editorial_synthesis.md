# 前10章盲读 + Benchmark + 作者实读｜总编合流判断

## 0. 核心结论

三份反馈其实在测三个不同层：

### 作者实读抓到
> **语言接口问题。**

表现为：
- 工程词；
- 占位名；
- 制度数据库字段；
- 抽象设备名；
- 事故报告语法。

### Phase A抓到
> **新读者理解 / 追读问题。**

表现为：
- 舍味 -> 当场筑基存在“兑换”误读风险；
- 第4章降速；
- 第5章最像恢复流程；
- 唐禾最容易工具化；
- 第5章异常味可能太弱；
- 周照 / 罗槐功能容易混。

### Phase B抓到
> **结构功能风险。**

表现为：
- 第3章以后职业恢复方向偏单一；
- 神秘线预算窄；
- 第5—10章章尾容易形成“许可阶梯”。

三者不能互相替代。

---

# 1. 当前最高优先级不是再改4—10章

作者实读暴露的“机械感”是高置信度问题。

而Phase B指出的：
- 后半偏平；
- 许可阶梯；
- 神秘线偏弱；

有一部分可能被“工程摘要格式”放大。

因此：

> **在没有正式正文前，不再因摘要平而新增事故、异常味、反转或新设定。**

先完成读者语言自然化和第一章真实文本，再验证结构体感。

---

# 2. 高置信度必须处理

1. 章卡工程语言不得直接进正文；
2. 普通物件必须从“功能占位”变成具体生活物；
3. Canon正式术语第一次出现必须先功能后名称；
4. 第2—3章事故必须从“事故报告”翻译成视觉 / 身体动作；
5. “舍味 -> 筑基”必须通过体验顺序而不是规则说明拉开因果；
6. 修籍、封位外环等开篇实现词必须经过命名必要性审查。

---

# 3. 中置信度，留给真实文本验证

1. 第4—10章是否真的偏平；
2. 第5—10章章尾是否仍像逐级许可；
3. 第3/6/7/9章筑基动作是否读起来重复；
4. 唐禾是否工具NPC；
5. 周照 / 罗槐是否容易混。

这些必须看：
- 对话；
- 人物行动；
- 场景空间；
- 节奏；
- 幽默；
- 具体工作内容。

结构摘要无法最终裁决。

---

# 4. 当前不要处理

1. 不追加第6—10章第二次异常味；
2. 不新增第二场强事故；
3. 不提前加余器；
4. 不为了追读改变永久失味；
5. 不把神秘线提前做成明显外挂。

---

# 5. 新增正文前闸门

正式采用：

> **Chapter Card**
> -> **Reader-Language Sheet**
> -> **Scene Spine**
> -> **Draft**
> -> **Prose Editor**
> -> **Text Blind Read**

Reader-Language Sheet专门负责：
- 名词；
- 口语；
- 普通物件具体化；
- 工程语言屏蔽；
- 术语第一次出现；
- 事故自然化。

这是之前缺失的一层。
