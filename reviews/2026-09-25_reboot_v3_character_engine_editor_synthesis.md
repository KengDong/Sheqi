# REBOOT-V3 Character Engine Editor Synthesis

# 0. Verdict

Character Engine Benchmark:
> **PASS / SUFFICIENT TO UNBLOCK CHARACTER COLLISION**

The report did not collapse into archetype copying.

The strongest transferable finding is:

> **A recurring character becomes a story engine when they have independent wants, offscreen agency, relationship memory, horizontal ties, and real leverage over the protagonist.**

The ordinary-chapter engine is:

> **Routine Action + Conflicting Small Wants + Old Relationship State + Consequential Choice -> Permanent Relationship Delta**

This is now the required design floor.

# 1. Shared Character Hard Constraints

Every ACTIVE candidate must satisfy all of the following.

## C1 Independent Want
Each high-frequency recurring person must want something that continues even if the protagonist disappears for one week.

## C2 Offscreen Agency
At least some recurring people must change the world state while the protagonist is absent.

## C3 Relationship Memory
Important interactions must change an observable later state:
- trust;
- debt;
- permission;
- responsibility;
- intimacy/distance;
- knowledge;
- public reputation;
- dependence;
- resentment.

“更熟了” is not enough.

## C4 Two-Way Leverage
At least two recurring people must possess something the protagonist cannot cheaply replace:
- access;
- labor;
- legitimacy;
- money;
- information;
- trust;
- emotional importance;
- social connection;
- specialized competence.

## C5 Horizontal Network
The cast cannot be a hub-and-spoke diagram centered entirely on the protagonist.

At least two meaningful recurring relationships must exist between non-protagonists.

## C6 Ordinary-Chapter Survival
No new monster / customer / mission / system / location.
Old people + old place + ordinary work must still generate a worthwhile chapter-sized conflict.

## C7 No Gratitude Shortcut
Being rescued, helped, housed, repaired for, or sold something does NOT imply permanent loyalty.

## C8 Decision Rule > Trait Tag
A character is defined primarily by:
> what they repeatedly prioritize under pressure,

not:
> 毒舌 / 社恐 / 吃货 / 高冷 / 腹黑.

## C9 Relationship Humor Must Evolve
Repeated banter is not chemistry unless prior events change its meaning.

## C10 Protagonist-Absence Test
If protagonist disappears for 24 hours:
> at least three recurring people still make decisions that create new consequences.

# 2. Candidate-Specific Character Requirements

## A01｜《怪物死了，地盘还在》

Must prove:
- tenants/residents are not management units;
- at least one resident can materially constrain the protagonist;
- at least one resident has a life goal unrelated to territory growth;
- residents form alliances/conflicts without protagonist mediation;
- old rent/protection/repair promises change later bargaining positions;
- success can increase other people's leverage over the protagonist.

Character failure pattern:
> 地盘+1 -> 住户加入 -> 忠诚+1 -> 提供功能.

If this appears:
> root warning.

## A02｜《末日先修水电》

Must prove:
- residents can reasonably oppose technically correct choices;
- professional correctness does not equal social authority;
- technicians/medical staff/residents can solve some problems without protagonist;
- family, dignity, property and fairness create conflicts that are not stupidity;
- old rationing/repair decisions return as political and emotional memory.

Character failure pattern:
> 居民犯蠢 -> 主角科普 -> 主角修好 -> 大家服气.

If repeated:
> root warning.

## A04｜《冒险者公会救援队》

Must prove:
- team members have career/family/fear/pride beyond “save people”;
- professional disagreements leave residue;
- survivors may deny, resent, sue, hide, depend, compete or reinterpret rescue;
- at least one old survivor creates trouble rather than gratitude;
- old incidents return through people and reputation, not only maps;
- protagonist-absent team decisions can succeed or fail.

Character failure pattern:
> 新事故 -> 救援 -> 幸存者感谢 -> 加入朋友圈.

If repeated:
> root warning.

## B10｜《灵气复苏，我开二手装备店》

Must prove:
- fixed customers have careers, budgets, status and long-term goals;
- second visits are changed by the first transaction;
- shop relationships involve leverage beyond price;
- old equipment history changes responsibility/trust/dispute;
- customers interact with one another;
- scenes exist with no new item introduced.

Character failure pattern:
> 新装备 -> 新客户 -> 扫描 -> 买卖 -> 下一个.

If repeated:
> root warning.

# 3. Cast Size Discipline

For each candidate:
- 1 protagonist;
- 3–5 recurring core people;
- optional 1 recurring antagonist/institutional counterparty only if structurally necessary.

Do NOT create a huge ensemble.

Reason:
> first-time + AI benefits from a small cast with dense relationship memory.

# 4. What Character Collision Must Produce

For each candidate:

## Protagonist Card
- concrete current desire;
- recurring behavior engine;
- decision rule under pressure;
- flaw/cost;
- social style;
- what they do when no task arrives;
- what makes them describable without the gimmick/system.

## Recurring Person Cards
For each:
- independent want;
- recurring behavior;
- what they do offscreen;
- leverage over protagonist;
- vulnerability to protagonist;
- one horizontal relationship with another recurring person;
- what old event they will remember;
- what would make them oppose protagonist.

## Relationship Network
Must include:
- protagonist <-> core people;
- at least two non-protagonist links;
- incompatible goals;
- at least one relationship that can improve AND worsen.

## 10–15 Collision Events
At least half must NOT begin with:
> protagonist receives a new task / monster / customer / emergency.

Each event must leave a measurable relationship residue.

## Protagonist-Absent Simulation
At least 3 mini-scenarios:
> protagonist absent 24h; what changes anyway?

## Ordinary-Chapter Test
At least 5 chapter-sized situations using only:
> old people + old place + old unresolved relationship state.

# 5. Anti-AI Hard Warnings

Reject / rewrite internally if the cast shows:
- same-voice dialogue logic;
- round-robin reaction;
- spreadsheet cast;
- convenient temporary desires;
- universal protagonist gravity;
- gratitude inflation;
- strawman conflict;
- dialogue-only memory;
- static banter;
- instant intimacy;
- symmetry addiction;
- tragic backstory used as agency substitute.

# 6. Selection Logic

Character Collision does NOT rank a winner.

For each candidate conclude:
- ACTIVE STRONG;
- ACTIVE BUT WARNING;
- RESERVE;
- DROP.

DROP only for structural character-engine failure, such as:
- recurring cast cannot generate scenes without new tasks;
- all people remain protagonist satellites after one root redesign attempt;
- relationship memory cannot change later decisions;
- protagonist has no stable non-gimmick behavioral engine.

No forced quota.

# 7. What Not To Borrow

Do not borrow:
- specific character combinations;
- existing relationship triangles;
- signature dialogue;
- signature jokes;
- organizations;
- character arcs;
- famous scene structures;
- living-author prose voice.

Learn only:
> reader function and causal relationship mechanics.

# 8. One Sentence

> **下一关不是“给四本书配几个讨喜角色”，而是证明这些人能在主角不发任务时继续活，并把旧关系越搅越厚。**
