# REBOOT-V4｜Fanqie Pool 04 Direct-Hit + Matched-Failure Deep Read

## 1. Exact Reader Pool Definition

本 Pool 不是泛化的“末日求生”，也不是“载具升级流”。

严格 Reader Fantasy 是：

> 世界越来越乱，而一个明确属于主角、会长期跟随主角的私有空间/载具/基地，持续变得更安全、更舒适、更富足、更有权力；每一次改善不只增加数字，还永久改变主角以后怎么生活、和谁一起生活、能做什么选择、必须承担什么责任。

因此至少需要同时满足四件事：

1. **Ownership continuity**：同一资产持续存在，Reader 能形成“这是我的”的稳定对象，而不是每个副本换一套装备。
2. **Life conversion**：升级改变真实生活方式——吃、睡、储存、移动、生产、交易、工作、休息、社交，而非只提升攻击/耐久。
3. **Social embedding**：住户、队友、职务、资源分配、规则、义务逐步进入资产内部；关系不是贴在资产旁边。
4. **Pressure feedback**：资产越强，选择越多，同时维护成本、责任、暴露面、资源需求或治理问题也上升；外部世界的新压力会重新考验旧资产。

只满足“车越来越大 / 火力越来越高 / 面板越来越长”，不够进入本 Pool 的强交付。

## 3. Core Pair A｜H1《苍穹列车车长》 vs W1《宝箱无限刷新》

### 3.1 Shelf / Package

#### H1
标题直接交付“末日逃亡 + 列车 + 车长”，而简介进一步把资产与人物结构锁死：

- 主角绑定苍穹列车；
- 列车是移动安全区；
- **幸存者越多，主角获得的生存点越多**；
- 生存点既可换物资/超凡物，也能升级列车。

这一步非常关键：资产成长不是与人物关系平行的两条线，而是“收人 → 养人 → 列车变强 → 能收更多人”的同一因果链。

#### W1
package 甚至比 H1 更直白地卖“末世移动豪宅”：

- 只有车内才能免受终焉辐射；
- 宝箱可升级汽车；
- 主角有刷新奖励能力；
- 车内有冰箱、电视、洗手间、厨房等舒适模块；
- 车外有武器与防御；
- 最终超级战车、人车合一。

所以 W1 的弱势**绝不能解释为“没有资产幻想”**。它恰好证明：把“安全屋、房车、武器、升级”词汇全部写进简介，也不自动形成资产复利。

### 3.2 First Screen / Ch1–3

#### H1
Ch1 在普通高铁/列车和现实灾变之间快速切换。主角获得“先驱者”能力并绑定载具，绑定后出现三种所有权感：

1. 列车只有他拥有绝对控制权；
2. 车辆传感器/广播/控制系统逐步成为他的感知与行动延伸；
3. 跟随者数量和跟随时间反过来增强他的成长。

到 Ch3，Reader 已经不只知道“他有一辆车”，而是知道**“这辆列车是他的身体延伸，也是未来人群要依附的秩序中心”**。

第一份真正属于主角的长期安全资产：**Ch1 即出现**。  
第一次产生“它以后会一直跟着我”的感觉：**Ch1–3 完成**。

#### W1
Ch1 也非常快：终焉世界明确宣告“只有车内才可免受污染”，车型宝箱是核心道具，资产生存价值成立。

但随后第一屏大量注意力分给：

- 系统规则；
- 聊天群；
- 开车型宝箱；
- 奖励刷新。

Ch3 的关键兴奋点已经明显变成“宝箱可刷高品级 → 丧尸等于奖励”，主角看到敌人首先想到的是产出；车辆更像吃奖励的承载平台。

W1 并不慢，它的问题是**核心因果中心被外挂奖励机制抢走**。

### 3.4 Earliest observable divergence

两本都在七章内完成“这辆车是我的长期安全资产”。

**最早差异不在有没有资产，而在升级的因果入口：**

- H1：人进入资产 → 人产生岗位/消耗/秩序 → 人又成为资产升级资源。
- W1：怪/箱进入奖励循环 → 奖励变模块 → 模块装到资产 → 再去找更高奖励。

前者天然制造“住户、分工、管理、责任”；后者天然制造“下一件模块是什么”。

这就是“资产复利”和“升级菜单”的第一处分叉。

## 4. Core Pair B｜H2《幽灵船》 vs W2《隐藏提示》

### 4.1 Shelf / Package

#### H2
简介把差异点固定在一条有名字的船——梦魇号。更重要的是，它明确声明：

- 航海求生；
- 灾害；
- 打造船只；
- 克系环境；
- “主角不会过得很惬意”。

这使资产不是无敌安全屋，而是**在持续危险里唯一可不断修补、理解、扩展的稳定物**。

#### W2
简介承诺“公路求生 + 丧尸 + 天灾 + 隐藏提示 + 多女 + 竞技”。车存在，但 package 没有把“同一辆车的生活复利”放在第一承诺位。

### 4.2 Ch1–20

#### H2
- Ch1：全民进入航海求生，黑雾追赶，主角在船舱醒来；生存空间立即成立。
- Ch2：梦魇号正式出现，特殊船身份冻结。
- Ch3：船的“垂钓诅咒”直接改变吃饭/取水方式；资产能力不是面板装饰，而是日常生存的利弊。
- Ch7：船上出现怪物扭蛋机等长期系统性设施/交互。
- Ch10：主角接触另一艘特殊船，尝试更换船只时找不到相关功能；“这不是随手换装备”的锁定感增强。
- Ch16–20：风暴持续恶化；Ch20 主角与苏娜结成船队，在高风力、低能见度中航行，船本身持续承受环境问题。

到 Ch20，Reader 得到的不是“船越来越强”单线，而是：
**船的特性 → 资源方法 → 交易 → 同伴 → 船队 → 风暴环境压力**。

#### W2
可访问正文索引较差，本轮主要依赖官方目录并抽检 later chapter，因此置信度低于 H2/W1：

- Ch2、Ch4：连续载具升级；
- Ch5：合成宝箱；
- Ch6：竞技奖励直接给女性仆从；
- Ch7–12：核心注意力转向柳如烟等关系/笑点；
- Ch13、Ch26、Ch34：连续竞技赛；
- Ch20：再次围绕熟人关系；
- Ch40 以后进入丛林副本/主支线任务链；
- Ch45 载具被偷，说明车仍会成为压力点，但更像单次任务冲突；
- Ch80 才出现“小队成员招募令”；
- Ch99 可见正文中已是房车，多个女伴共同生活；
- Ch100 自由购物区、Ch110换区、Ch121甚至在教室内长期行动。

车辆确实长期存在，不能说“资产消失”。但故事的主动发动机大量发生在**竞技/副本/任务/区域/女伴关系**，车常常负责把人物送到下一内容节点，而不是每轮都因为它过去积累的结构而改变下一轮问题。

| Ch20–50 | 更强卡车 | 开箱、极端天气、车辆升级、重炮、火焰等 | 多数是 | 生存舒适继续，但叙事标题重心转向战斗/奖励 | 人物对资产结构影响弱 | 打更强怪/进遗迹 | 敌人强度上升 | 看“下一模块” |
| Ch70–100 | 高级战车 | 金色模块、伽马/超型卡车等 | 是 | 生活层升级证据相对弱于火力层 | 队友/组织开始出现但非资产治理核心 | 更大范围碾压 | 数值与敌人一起升级 | 体量/稀有度 |
| Ch180–255 | 无限战车/高阶形态 | Ch188/189升级、Ch214战车升级、Ch239模块更新、Ch244人车合一 | 是 | 后期从“住在车里”更偏“车=超级武器/自身形态” | 关系未形成稳定住户/治理复利证据 | 进入神话级战斗 | 战力升级成本 | 最终升级/武器化，而非家园社会化 |

**关键：W1 不是没有 compounding，而是 compounding 主要发生在“模块/战力树”，较少发生在“生活系统×关系系统×责任系统”的交叉处。**

### 5.4 W2《隐藏提示》

| Stage | 资产 | 新增/变化 | 生活/关系 | 风险与责任 | 结论 |
|---|---|---|---|---|---|

## 6. What Actually Creates “This Is Mine”

本轮证据把“拥有感”拆成六个可观察来源：

### 6.1 Exclusive agency
不是系统说“归属你”，而是主角能做别人不能做的决定。

H1 的独占列车控制权最强：停、走、开门、广播、车内秩序都收束到车长身份。

### 6.2 Memory of past investments
Reader 记得“这个空间以前是什么样”，所以新变化有比较基线。

H2 最明显：同一艘船从破旧特殊船一路经历燃烧、冻结、维修、扩建、建筑、生态；旧伤与旧功能不消失。

### 6.3 Recurrent domestic use
床、冰箱、食物、仓库、商店、作坊等只有在后续持续被使用时才是资产；如果只是升级当章展示一次，它仍只是奖励。

W1 Ch5–7 已经给出床/冰箱/房车目标，但后续 title/function 记录显示，战斗模块和宝箱获得更高叙事频率。这说明“做出生活模块”只是第一步。

### 6.4 People who depend on the asset
一个人住在车里只能制造舒适；多人依赖同一空间，才自然长出：

- 谁能上来；
- 谁负责什么；
- 谁吃多少；
- 谁有权限；
- 谁承担危险；
- 谁可以留下。

H1 的“跟随者=成长资源”把这个结构从最早期就机械绑定。

### 6.5 Cost and vulnerability
无敌安全屋会杀死复利感，因为旧资产不再需要被理解。

H2 的船会烧、会冻、要修、会被新海域重新考验；越升级越不是“免疫世界”，而是获得更多解决问题的工具。

### 6.6 Option expansion
最有效的升级不是“攻击+20%”，而是以前不能做的事现在能做：

- 长期储粮；
- 收更多人；
- 开店；
- 生产；
- 研究；
- 组船团；
- 与基地连接；
- 建立岗位。

Reader 感到的不是数字，而是未来故事选择面变宽。

## 7. World Deterioration vs Private-Space Improvement

强样本都在维持一种稳定反差，但方式不同。

### H1
外部：血月、地震、诡异、失序、资源风险持续扩大。  
内部：列车从临时逃生工具变成有岗位、有物资、有居住/生产设施的秩序空间。

因此每次“回到列车”都具有情绪价值：外面越乱，里面越像人类生活。

### H2
外部：黑雾、风暴、极寒、异常海域不断换压力。  
内部：船并不绝对安全，但主角能留下修理、武器、实验、种植、商业等长期痕迹。

它的反差不是“外面地狱/里面天堂”，而是：
**外面不可控，只有这条船是我能逐步理解和改造的东西。**

### Weak contrast
W1 早期其实做出了“别人挨饿/我吃甜点、别人普通车/我房车化”的强反差，但后续反差越来越依赖“别人装备差/我装备金色、别人火力差/我火力大”，从生活反差退化成战力反差。

## 8. Character / Relationship Engine

### H1
最强关系机制不是“主角认识很多人”，而是**人必须在列车这个资产里有位置**：

- 车长；
- 助手；
- 职务；
- 新人；
- 资源领取与贡献；
- 后续经营/治理角色。

旧人物可以因为岗位、资源、权限和生存责任在没有新怪物时继续制造冲突。

### H2
人物更少、更慢，但关系与资产的专业功能逐步咬合。苏娜等固定关系不是“一次救援后消失”，而是共同航行、研究、交易、升级与冒险的长期伙伴。船提供了关系的固定舞台。

### W1
早期独狼设计使资产舒适度很强，但“住户/岗位/规则/分配”迟迟不成为主干。后来有人物和组织，也更多围绕战斗阵营/高阶危机，而不是“同一辆车内部生活怎么变化”。

### W2
关系数量增长得很快，但很多角色以竞技奖励、恋爱/性张力、任务同伴进入。关系的新增不需要资产结构发生变化，因此“多了一个人”常常只是人物卡增加，而不是资产生态增加。

## 9. Pairwise HIT vs WEAK Delta

### 9.1 H1 vs W1

**Both have**
- 末日移动载具；
- 载具是安全基础；
- 高频升级；
- 火力/防御强化；
- 外部世界持续危险；
- “别人更差，我更好”的反差。

**Hit premium**
- H1 把“人口/关系”直接写进资产升级经济；
- 主角身份“车长”就是资产权力结构，不是外挂附带称号；
- Ch10 之前资产已同时承担移动、庇护、战斗、社会身份；
- 升级后不断生成新的运营问题，而不是只生成下一档战力。

**Weak divergence**
- W1 Ch1–3 先把最大兴奋点交给“宝箱刷新”；
- Ch5–7 虽有优秀的房车生活改善，但随后高频标题迅速回到宝箱、模块、火炮、遗迹、升级；
- 后期升级仍持续，但越来越走向“超级武器/人车合一”。

**Category baseline**
- 车升级、资源、箱子、极端天气、别人羡慕，都不是 execution premium。

**Alternative explanations**
- H1 是2026新书，W1发布时间更早；
- 推荐流量/封面/投流不可见；
- H1 exact current in-read 本轮只能用项目已冻结榜单信号，官方页不直接显示同口径数字。

### 9.2 H2 vs W2

**Both have**
- 全民/游戏化求生；
- 持续载具；
- 资源获取；
- 同伴增加；
- 多地区/多环境；
- 后期载具升级。

**Hit premium**
- H2 的特殊船从 Ch2 开始就是故事规则来源：吃什么、怎么交易、能否航行、如何抵抗天气，都被它影响；
- 旧资产会被新环境重新伤害；
- Ch225 仍用“已有建筑/植物/船体特性”组合出新能力和新问题；
- 一千章后还是同一资产的演化，不靠淘汰旧家园维持新鲜。

**Weak divergence**
- W2 在 Ch6 起就大量把注意力给竞技奖励和新女伴；
- Ch40后副本/任务化显著；
- 房车和乘员确实存在，但常常只是下一段内容的运输容器。

**Confounders**
- H2 是长程大样本，W2仅30.1万字；
- 作者能力、曝光、书测数据不可见；
- W2 早期正文索引不足，部分判断依赖官方目录功能结构和 Ch99/100/121等可访问正文，置信度中等。

## 10. Reader-Reaction Evidence

评论只作定性支持，不当作代表性统计。

### H2
番茄关键词页可见早期读者反复称赞：

- 物资获取不轻松；
- 主角/女主有独立行动力；
- 风暴、克系航海与特殊船组合有新鲜感；
- 有读者直接要求“把幽灵船特点多写点”。

这和长程证据一致：Reader 不只是想看“船等级提高”，而是希望这条船本身持续产生独特内容。

### W1
同一番茄相关帖子同时出现正负反馈：

正反馈直接把爽点概括成“别人求生我度假”，证明资产舒适反差本身具有吸引力。

负反馈集中在：
- 前几章聊天频道占比过高，影响开篇吸引；
- 主角体能/武器使用等可信度；
- 资源紧缺时的行为逻辑；
- 关系/交易行为与末日压力不一致。

因此 W1 的弱势更像**执行和因果可信度问题叠加在强 premise 上**，而不是市场不想看这个 Reader Fantasy。

### S2《海洋求生…》
可见评论有人抱怨“每次登岛就有人偷家”等安全边界问题。这个反应有参考价值：当书把船卖成长期私域时，Reader 会真实审查“家”的权限与防守是否可信；安全感不是封面词。

## 11. Failure Signatures

### 11.1 Upgrade menu substitution
最危险的伪复利：

> 找资源 → 开箱 → 新模块 → 数值变大 → 新地区 → 再找资源。

它可以很爽，但每一轮结束后除了数字，生活与关系没有永久变化。

W1 是本轮最清晰样本：它真的有房车生活，但中段后 reward vocabulary 过度集中在等级、模块、火力、品质。

### 11.2 Asset as taxi
资产存在，却只负责把角色送到下一个副本。

W2 中后段的副本/竞技/区域链更接近这一风险。

### 11.3 Reaction-shot economy
用聊天群不断重复“别人震惊/羡慕”替代资产实际改变生活。

W1 的读者评论对开篇聊天频道占比有直接抱怨，这个问题比“升级太少”更早伤 first-screen conversion。

### 11.4 Relationship attachment without asset integration
“又多一个女伴/队友”不等于资产复利。只有当新增的人改变岗位、空间、资源、规则或未来选择，人物才真正进入资产 Ledger。

### 11.5 Invulnerability
如果升级让资产彻底免疫旧问题，Reader 很快只剩等下一个更大的怪。

H2 的相反做法更有效：船越强，仍然会烧、冻、损坏，需要旧功能重新组合。

### 11.6 Scale inflation without option expansion
从10米车变100米车、炮口从一门变十门，只是 scale。  
真正 escalation 应让主角以后能做“以前不能做的事”。

## 12. Newcomer Execution Burden

**Domain research burden：中等。**  
不要求专业军事/工程级知识，但车辆、供给、能源、空间、食物、维修一旦进入正文，就会被 Reader 用常识审查。

**Logic-consistency burden：高。**  
资产是长期对象，早期写过的容量、规则、权限、耗能、维护如果后面忘掉，会形成明显硬伤。

**Scene-generation burden：高。**  
不能靠每十章换一个新地图救场；同一空间必须反复产生不同类型场景。

**Character burden：高。**  
要让“住户/队友”不是装饰，而是拥有独立欲望和岗位，且能反过来改变资产。

**Long-run escalation burden：很高。**  
最容易从“家越来越好”滑成“武器越来越大”。

**Platform sensitivity：高。**  
当前 HIT 和 W1 weak 对比说明，强 premise 仍可能在前三章被聊天、说明、奖励日志稀释。资产幻想必须在 First Screen 就被“体验”，不能只被“解释”。

常见 novice failure：
- 先写十页系统说明再让资产工作；
- 每次升级只列新设施，不让设施回返；
- 新成员只增加后宫/队伍人数，不增加责任；
- 资源永远够，升级没有取舍；
- 世界灾难只负责提供怪物，不改变住法；
- 为了升级不断换载具，破坏 Reader 的所有权记忆。

## 13. Substitution Space｜Market Function Only

### 13.1 Overused delivery patterns
- 宝箱/抽奖 → 模块；
- 车辆等级数字；
- 火力口径升级；
- 聊天群震惊；
- “别人挨饿，我吃大餐”一次性反差；
- 每地区一套新怪/新遗迹；
- 新女伴/新队友作为奖励；
- 数值更高的同类武器替代旧武器。

### 13.2 Repeated reader functions proven by hits
- 一眼认得出来、不会轻易替换的长期资产；
- 回到资产本身就是情绪结算；
- 外界恶化与内部秩序改善形成长期反差；
- 升级改变生活习惯，而不是只改战力；
- 旧设施在新灾难里重新发挥作用；
- 人口进入后自然出现岗位、权限、供给、责任；
- 资产越大，问题越多，但解决问题后又扩大未来选项。

### 13.3 Weakly served functions
- 升级后真正持续数十章的生活改变；
- 维修、耗能、库存、空间等成本与爽点并存；
- 同一资产内部规则逐步制度化；
- 旧设施之间组合出新能力，而不是被新模块淘汰；
- 资产承载共同记忆和关系历史；
- 新环境重新测试旧资产，而不是直接换新家。

这些只是 Reader-function 空间，不是新小说 Concept 授权。

## 14. Evidence Limitations

1. 番茄动态在读数字会漂移；H2 同一作品近周关键词缓存出现35.5–45.6万不同数值，项目旧冻结为51.9万。报告保留区间和日期，不把缓存差异当趋势。
2. H1 官方 work page可确认27.6万字、134章及2026-09-25更新，但本轮未获得与榜单完全同口径的实时在读数，因此沿用项目2026-09-26冻结的约12万级 current signal。
3. W2 早期 chapter body 搜索索引不完整，Ch1/3/7/10/20 中部分只获得官方目录而非完整正文；later Ch99/100/121有可访问正文。相关结论已降置信度。
4. H2 部分具体章节正文通过公开文本镜像抽检，作品元数据与目录均以番茄官方页为锚；不复制长文本。
5. 作者曝光/投流/推荐量不可见，未把“当前在读低”解释成单一文本因果。
6. S1/S2/S3 只作为边界样本，不用于证明 exact Pool 的因果。
7. 不存在足够证据证明“只要做出资产复利就一定成为 HIT”；本轮证明的是 HIT 与 matched weak 在交付结构上的稳定差异。

## 15. Pool-only Conclusions

### Now proven

**P1｜“私有安全资产复利”是比“求生升级”更窄也更真实的 Reader Fantasy。**  
H1/H2 的核心优势都不是拥有更多奖励，而是同一个资产永久改变生活、关系和未来选项。

**P2｜第一份资产要极早出现，但更关键是极早建立“不可替代性”。**  
H1 Ch1–3 完成独占控制和身体延伸；H2 Ch2 就命名梦魇号，并让船的特殊属性直接改变生存方法。

**P3｜真正的 compounding 单位不是数值，而是“以后会继续存在的状态”。**  
床、仓库、岗位、同伴、实验室、商店、种植、维修义务、规则，只有在后续回返时才算复利。

**P4｜人物进入资产，必须同时带来价值和成本。**  
H1 用“幸存者→生存点”把收人变成收益，又自然带来供养与治理。纯粹“又来一个角色”不足以建立资产感。

**P5｜升级必须扩大选择空间。**  
从逃命到储备、生产、交易、组织、治理，比“炮更大”更能延长同一 Reader Fantasy。

**P6｜旧资产必须被新世界重新出题。**  
H2 的燃烧、冻结、维修、拓展证明，强资产不是无敌空间；它要在新环境里反复接受检验。

**P7｜W1 证明了一个重要反事实：把“安全屋、房车、冰箱、床、火力、无限成长”全部写齐仍可能弱。**  
它的前7章甚至非常准确地完成了“车是第二个世界”。真正差异在于后续故事更常由宝箱/模块/火力刷新，而不是资产内部生活、关系和责任继续复合。

### Still not proven

- 不能证明 H1 当前成绩主要由资产结构而非推荐/封面/作者因素造成。
