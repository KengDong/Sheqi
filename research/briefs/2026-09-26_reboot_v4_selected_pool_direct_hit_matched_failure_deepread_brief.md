## 1. Highest Question

For each retained Fanqie Reader Pool:

> **Why do some current / recent DIRECT works actually acquire and retain readers, while similarly packaged works in the same Reader Fantasy remain weak?**

Do not answer with:
- "题材热门";
- "文笔更好";
- "节奏更快";
- "系统更爽";
- title/tag similarity alone.

The unit of analysis is:
> **Reader Fantasy delivery under matched market conditions.**

## 4. Sample Design

For the assigned pool, build:

### A. CORE DIRECT HITS
Target:
> **2 CORE HIT works**

Requirements:
- exact / near-exact Reader Pool match;
- measurable current or recent Fanqie performance;
- enough text exists to inspect early retention;
- at least one should be a current/recent-entry signal where possible;
- newcomer / low-visible-author-credit evidence is preferred but not mandatory.

### B. SUPPORT HIT
Target:
> **1–2 SUPPORT HIT works**

Use to test whether the mechanism repeats beyond the core pair.

### C. CORE MATCHED WEAK CONTROLS
Target:
> **2 CORE WEAK controls**

Match as tightly as possible on:
- Reader Fantasy;
- delivery vehicle / title promise;
- publication era;
- length / opportunity to accumulate readers;
- platform;
- update / completion status;
- author visibility where observable.

A weak control is NOT automatically a causal "failure".
If confounders remain, label them.

### D. OPTIONAL CONTROL
May include:
- VETERAN CONTROL;
- IP / SEQUEL CONTROL;
- MEGA HIT CONTROL;
- NEAR pool control.

These must never be used as clean newcomer-entry proof.

## 5. Matched-Failure Integrity

Do NOT force a false matched pair.

For every weak control, record:
- current measurable weakness signal;
- word count / chapter count if available;
- completion / update state;
- age / publication timing if available;
- author-credit signal if available;
- major confounders.

Use labels:
- MATCHED WEAK CONTROL;
- PARTIAL MATCH;
- WEAK CONTROL ONLY;
- UNUSABLE AS CONTROL.

If no clean matched weak sample exists:
> say so explicitly.

Do not upgrade "under 1000 current readers" into proof that opening execution caused failure.

## 6. Deep-Read Depth

For each CORE HIT and CORE WEAK control:

### Package layer
Inspect:
- title;
- blurb / synopsis;
- tags / category;
- visible cover promise if accessible;
- immediate Reader Fantasy promise;
- what a stranger expects before opening.

### First-screen / Ch1–3
Read enough actual text to reconstruct:
- first information order;
- protagonist position;
- first tension / desire;
- premise activation;
- first protagonist choice;
- first visible reward / danger;
- first social revaluation;
- first relationship constraint;
- first "I know what this book repeatedly gives me" moment.

### Ch1–20 retention map
Do not rely only on summaries.

Build a compact event/function ledger across Ch1–20, with explicit checks around:
- Ch1;
- Ch3;
- Ch7;
- Ch10;
- Ch20.

Track:
- Reader Fantasy deliveries;
- reward intervals;
- unresolved promises;
- relationship changes;
- permanent state changes;
- escalation;
- repetition / stagnation.

If chapters are unavailable, document the access limitation and downgrade confidence.

### Long-run check
Where enough text exists, sample later state around:
- Ch50;
- Ch100;
- current / later arc.

Question:
> What survives after the initial novelty is no longer novel?

## 7. Required Analysis Grid

For each CORE sample answer:

### A. Acquisition
Why does the package earn a click from a stranger?

### B. First-screen conversion
What happens before the Reader Fantasy is actually felt?

### C. Promise-to-payoff delay
How many chapters / scenes before the book pays its core promise?

### D. Repeatable fantasy loop
What exact experience can repeat 20+ times without merely changing nouns?

### E. Protagonist engine
What does the protagonist repeatedly WANT / DO that creates story?

### F. Character / relationship engine
Can old relationships create new reading desire without adding a new case / monster / item / setting?

### G. Compounding state
What permanently remains after each mini-arc:
- status;
- assets;
- relationships;
- secrets;
- obligations;
- territory;
- ability combinations;
- public reputation;
- institutional position?

### H. Escalation
How does the same Reader Fantasy become bigger rather than simply more numerous?

### I. Failure signature
Where does the weak control:
- delay the fantasy;
- substitute explanation for experience;
- repeat one beat;
- fail to compound;
- flatten characters;
- overuse reaction shots;
- lose causal pressure;
- drift away from the promised fantasy?

Do not assume these failure modes; prove which ones actually occur.

## 8. Pairwise Delta

For each CORE HIT vs CORE WEAK pairing, produce:

1. what both books have;
2. what the hit does that the weak control does not;
3. what is merely category baseline;
4. what is true execution premium;
5. earliest observable divergence;
6. whether the divergence persists by Ch20;
7. alternative explanations / confounders.

This is the most important section.
