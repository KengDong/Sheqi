# 一、角色分工

## 开头GPT：修订工程师
本轮不再负责“发明更多设定”，而负责把现有争议项压成可冻结版本。

### 任务A｜重写五次大境跃迁
按独立审核要求，重写：
- 炼气 -> 筑基
- 筑基 -> 金丹
- 金丹 -> 元神
- 元神 -> 法相
- 法相 -> 洞天

每境必须写清：
1. 这一境真正新增的生命/战斗能力
2. 修积阶段完成什么
3. 明悟阶段解决什么
4. 续我时到底在重构什么
5. 完整续我为何需要时间
6. 资源具体保护/托住什么
7. 借载设施替本人承受什么
8. 舍弃如何降低续我负担
9. 失败具体会发生什么

### 硬约束
- 不得写“某境最适合舍某类人格”的固定攻略。
- 不得把高境修炼写成道德考试。
- 洞天重点是“个人道路与外部天地形成稳定、可收放的规则边界”，不是“学会包容别人”。
- 大宗门可以规模化借载；限制来自适配、占用、稀缺介质/地脉、操作、耗材、维护，而不是凭空增加万能冷却。

### 任务B｜陆野第一次舍味最终闭环
在现有事故结构上，只补最关键的一处：

> 陆野在事故发生前，味觉已经通过正规舍备流程确认：
> - 它是真实可舍的我相；
> - 边界清楚；
> - 对陆野这次筑基续关来说，减负“足够”。

事故只破坏封位，不临时制造突破资格。

同时检查：
- 为什么味觉不需要“陆野特别爱吃”才能合法；
- “爱吃”只负责情绪重量，不负责规则合法性；
- 漏舍、尝余、官方登记逻辑是否仍然闭环。

### 任务C｜三问模型落地
把原“双判定”改写成作者侧三问：

> 真不真？  
> 切不切得开？  
> 切了够不够？

要求分别说明：
- 世界内正规舍务流程如何自然体现这三问；
- 哪些只属于作者工作模型，哪些读者会看见；
- 不得做成三个数值条；
- 不得发明万能人格扫描器。

### 任务D｜术语实战试写
不要继续做术语表审美讨论。

至少写10段真实场景短对白/短叙述，覆盖：
1. 驿货行管事
2. 舍务窗口
3. 舍务医师
4. 军人黑话
5. 普通百姓
6. 宗门长老
7. 教材/公文
8. 黑市舍师
9. 富家子弟谈借载
10. 陆野本人吐槽

对比测试：
- 修积 / 明悟 / 续我
- 积 / 悟 / 续
- 完整续我 / 借载续我 / 舍弃续我
- 正破 / 借载 / 舍破
- 全续 / 借续 / 舍续（如果仍想保留，必须用真实对白证明）
- 缺位 / 余位

最终只给：
- 建议冻结
- 建议保留俗称
- 建议淘汰
三类。

### 任务E｜舍眠最终规则
保留“清醒连续性”，增加硬约束：

> 恢复债可延后、可拆分，但不能消失。

必须说明：
- 神魂归整期间不能同时正常警戒/工作/悟法；
- 无眠者为什么有职业优势；
- 为什么不成为全民最优；
- 为什么又不是完全没人会选。

### 外部借鉴要求
本轮不再做18部级别大调研。
只允许对仍有争议的点做**针对性复核**：
- 境界突破成本
- 术语自然度
- 睡眠/恢复漏洞

最多补查3—6个高相关样本。
必须说明“借的是功能，不是表面”。

### 开头GPT最终交付
新建一个 review-pending 文件：

`reviews/2026-09-20_v1_freeze_patch_v2_for_final_audit.md`

文件必须包含：
1. 五境最终候选表
2. 三问模型最终文字
3. 陆野第一次舍味闭环补丁
4. 舍眠最终规则
5. 10段术语实战试写
6. 建议修改哪些Canon、逐文件列出
7. 哪些问题仍不建议冻结
8. 自己主动列5个最担心的漏洞

**不得直接改Canon，不得宣布V1.0完成。**

## 审核GPT（本会话GPT）：最终红队总编
收到 V2 Patch 后负责：

1. 对照现 Canon 做逐条冲突检查。
2. 再做一次“读者钻漏洞”攻击。
3. 特别检查：
   - 是否产生境界—人格最优攻略；
   - 是否让舍台变成万能扫描器；
   - 是否让借载被人为削弱；
   - 是否让高境修炼带隐含道德评判；
   - 是否为了术语整齐牺牲人话；
   - 是否让陆野第一次舍味显得作者特批。
4. 对每条 Patch 给：
   - Accept
   - Accept with revision
   - Reject
5. 输出最终 Freeze Decision。

只有作者确认后，审核GPT才执行：
- 修改Canon
- 更新STATE
- 更新DECISIONS
- 更新CHANGELOG
- 关闭对应P0 Issues
- 形成 Bible V1.0 状态

## 作者（你）：只做真正需要人拍板的选择
你不需要再替GPT做研究，也不需要检查每个技术细节。

你主要负责5类决定：

### 1. 主题偏好
例如：
- 更愿意让舍弃偏“人生代价”还是偏“修炼工程”
- 高境舍弃要不要越来越触及关系/身份

### 2. 语言口感
例如：
- “完整续我”是否有仙侠味
- “缺位”是否顺耳
- 是否保留“正破”这个民间词

### 3. 主角人格
例如：
- 陆野到底有多爱吃
- 他第一舍时是轻描淡写，还是已经知道自己舍得很心疼

### 4. 灰度边界
例如：
- 正规舍务体系应该多可靠
- 黑市有多危险
- 大宗门借载工业化到什么程度

### 5. 最终批准
你只需要回答：
- 这个规则我认不认
- 这个词我顺不顺
- 这个人物选择我信不信

不需要亲自补逻辑；逻辑由两个GPT互相打。

# 二、工作节奏

## Round 1｜开头GPT修订
输出 V2 Patch。

## Round 2｜独立审核
审核GPT红队，不改Canon。

## Round 3｜作者讨论
只讨论仍有分歧的3—8个点。

## Round 4｜最终落库
作者批准后，由审核GPT统一修改Canon和项目状态。

## Round 5｜冻结
若不存在P0系统漏洞：
> Bible V1.0 Frozen

随后停止继续扩底层世界观，转入：
> 核心人物组 -> 第一卷中央因果链 -> 第一批故事单元 -> 卷纲 -> 章节卡 -> 初稿

# 四、本轮成功标准

不是“规则越多越完整”。

成功标准只有四个：

1. 作者能用一句人话解释。
2. 角色能在对白里自然说。
3. 读者很难用三分钟整理出最优攻略。
4. 写到几十万字后仍不需要频繁Retcon。

满足这四条，才值得叫 Bible V1.0。
