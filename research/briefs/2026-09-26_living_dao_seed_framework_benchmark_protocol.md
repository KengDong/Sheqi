# AUTHOR requirement

From this point forward, every new window that defines framework-level material MUST benchmark real popular novels before designing.

This includes:
- world rules;
- Dao-seed rules;
- cross-world rules;
- dual-protagonist character design;
- relationship engine;
- Ch1–20 structure;
- Ch20–100 progression;
- long-horizon architecture;
- packaging / title.

"Reference popular novels" is NOT a decoration section.
It is a hard input dependency.

# Why this exists

Previous project failures repeatedly came from:
1. extracting an abstract lesson from a hit;
2. then letting the design window free-invent;
3. producing something logically coherent but visibly less desirable than the reference.

The new rule:
> benchmark first, map functions second, design third, red-team against the benchmark fourth.

# Required benchmark stack for EVERY framework window

Each window must use at least:
- 1 DIRECT / near-direct current hot reference;
- 1 current or recent strong work proving the specific commercial function;
- 1 mature / long-run control proving the function survives after the opening.

The benchmark must be specific to that window.

Do NOT reuse the same three books mechanically for every task.

# Mandatory workflow inside every future window

## Step 1｜Freeze benchmark evidence
Before touching our concept, write:
- reference title;
- actual opening / early engine;
- first concrete payoff;
- what repeats;
- what accumulates;
- what changes socially;
- what is deliberately delayed;
- failure mode of shallow imitation.

## Step 2｜Function extraction
For each borrowed lesson:
> reference does X because Y.

Never:
> "this book is hot, so use school / double-world / system."

## Step 3｜Design mapping
Every major proposed A3 rule must state:
- which benchmark function it is trying to achieve;
- how our implementation differs;
- why our version is not obviously weaker.

## Step 4｜Side-by-side red team
Before PASS, answer:
> If our design and its nearest reference are shown side by side to a stranger, is the reference immediately more interesting?

If yes:
> revise before handing off.

## Step 5｜Preserve causal chain
Do not borrow isolated cool pieces.

The chosen rule must connect:
> opening life pressure
→ first payoff
→ repeat engine
→ social revaluation
→ relationship growth
→ larger world access.

# Forbidden behavior

No framework window may:
- start writing our solution before benchmark extraction;
- invent a strange profession to create access;
- use "system" as explanation for missing causality;
- use world mystery to hide a weak daily loop;
- stack every good benchmark feature into one book;
- copy names, scenes, event order, character configurations or living-author style.

# Framework phase sequence

## Gate 1｜Benchmark Dossier
Role:
> `living_dao_seed_benchmark_scout`

Output:
- direct/near/control benchmark map;
- early-loop mechanics;
- dual-world asymmetry mechanics;
- two-protagonist / persistent-relationship mechanics;
- expansion gradient;
- anti-copy boundaries.

NO A3 design.

## Gate 2｜Core Logic
Role:
> `living_dao_seed_logic_architect`

Can begin only after Gate 1 PASS.

Must define:
- what a Dao seed really is;
- why modern society uses it;
- why the living resonance exists;
- what can / cannot cross;
- why these exact two people connect;
- what information asymmetry is structural rather than convenient.

## Gate 3｜Two-Protagonist Character Engine
Role:
> `living_dao_seed_character_architect`

Must use Gate 1 relationship benchmarks + Gate 2 hard logic.

Define:
- each protagonist's independent desire;
- independent cast / problem;
- recurring behavior;
- disagreement;
- why reader follows either line even if the other protagonist disappears for 5 chapters.

## Gate 4｜Ch1–20 Commercial Engine
Role:
> `living_dao_seed_early_engine_architect`

Must benchmark:
- 《九种魔药》
- 《原来我是仙道天骄》
- 《没钱修什么仙？》
plus any better current direct comps found at execution time.

Must prove:
- Ch1 hook;
- Ch3 "I want another interaction";
- 3 distinct information-gap payoffs;
- first public revaluation on both worlds;
- no lore dump.

## Gate 5｜Ch20–100 Expansion
Role:
> `living_dao_seed_horizon_architect`

Must benchmark long-run controls:
- 《我有一个修仙世界》
- 《我的化身正在成为最终BOSS》
- other current long-form comps found by scout.

Must prove:
- neither world becomes dead weight;
- neither protagonist becomes helper NPC;
- same pleasure grows in scale rather than being replaced by new gimmicks.

## Gate 6｜Framework Red Team
Role:
> `living_dao_seed_framework_redteam`

No new invention.
Only check:
- causal gaps;
- weak imitation;
- AI abstraction;
- over-complex rules;
- whether any benchmark is obviously more attractive at the same stage;
- whether Ch1 promise and Ch100 experience are still the same book.
