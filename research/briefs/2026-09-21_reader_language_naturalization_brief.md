# 任务A｜全量扫描，不只修作者指出的词

扫描前10章所有可能进入正文的：
- 专名；
- 设备名；
- 职业名；
- 流程名；
- 食物；
- 药；
- 工具；
- 设施；
- 行业简称；
- 抽象机制句；
- AI式名词串。

每项分类为：
- AUTHOR-ONLY
- PLACEHOLDER
- CANON-FORMAL
- IMPLEMENTATION-TERM
- EVERYDAY
- NEEDS-DECISION

不得只检查：
> 修籍 / 货签夹 / 热汤 / 转运架。

目标是把作者尚未注意到的也抓出来。

# 任务B｜建立三层语言表

对重要词建立：

| 概念 | 作者工程名 | 正式/公文语 | 行业口语 | 普通人物口语 | 读者第一次怎么认识 | 状态 |
|---|---|---|---|---|---|---|

其中 Canon词：
> 不改概念，只设计自然进入方式。

Implementation词：
> 可以提出更自然的候选，但不能自行升Canon。

# 任务C｜前三章“具体生活物”清单

必须具体化或至少给2—3个强候选：

- 第一章夹货牌的东西；
- 第一章廉价正常食物 / 汤；
- 排班凭证 / 修行凭证的实际载体；
- 夜班工作环境普通器物；
- 第2章重货运输设备；
- 导向结构；
- 退回舍务处的具体封存物；
- 舍台正常外观；
- 第3章事故后喝的普通药。

选择标准：
1. 人能想象；
2. 人会这么叫；
3. 符合阶层 / 时代 / 工作；
4. 不抢核心设定；
5. 不需要解释词典。

不要为了“仙侠味”造生僻词。

# 任务D｜事故人话翻译

保持已冻结物理因果不变。

分别写：

### D1 作者工程版
保留精确因果，用于QA。

### D2 普通读者动作版
不用：
- 正常安全包络；
- 服务位入口；
- 辅助制动/牵引结构；
- 持续稳定操作权限；
- 低阶可控范围。

只用：
- 看到；
- 听到；
- 甩；
- 卡；
- 撞；
- 裂；
- 拉；
- 稳；
等可感动作。

### D3 现场人物口令版
模拟真正事故时人物只会喊什么。

目的：
> 证明同一事故不用技术报告也能看懂。

# 任务E｜舍味 / 筑基的体验翻译

必须解决盲读误读：

> 舍味 = 交代价换筑基。

不能靠旁白解释规则。

提出2—3种体验呈现方案，要求都能让读者直觉感到：

1. 舍契先造成**缺失 / 减负**；
2. 筑基随后是原有修炼终于完成；
3. 能力来自筑基，不来自味觉本身；
4. 漏舍又是第三件独立事故结果。

禁止：
- 系统提示；
- 数值下降；
- “兑换”语言；
- 一句规则科普解决。

---

# 任务F｜前10章AI机械语言红队

专门找这些病：

- 名词叠名词；
- 斜杠选项；
- 三层定语；
- “当前/本次/该项/相应”过多；
- 抽象动词；
- 作者免责声明；
- “这不是X，而是Y”频繁；
- 人物口中像制度文件；
- 所有东西都被统一命名；
- 所有场景都先分类再发生。

至少列：
> 30个高风险表达或句型来源。

不是为了逐字改章卡，而是形成未来自动检查规则。
