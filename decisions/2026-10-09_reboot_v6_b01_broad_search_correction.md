# REBOOT-V6｜作者第三次明确纠偏：广搜大库，不限定只搜几个

## 作者原话
“多搜索点不好吗？”

作者针对先前 B01-V2 的“第一批最多 5–7 张精选事件卡”、少量强案例即 STOP 表达不同意见。对其意图的忠实落实：**不要把精选展示数量误当成搜索数量或素材库规模上限**。

## 最高要求
**搜索尽可能广、严格核验、持续扩容、分层呈现；只有作者注意力有限，不是资料库有上限。**

“高效”同时包括：
- 正文高效：具体故事尽早兑现爽、笑、惊奇、悬念并持续产生新变化；
- 研究高效：搜得多、去重快、先验证明显有潜力的线索，避免在普通书上平均花工夫；
- 决策高效：用户先看可复述场面及出处，不被海量弱素材淹没。

## 数量设计：容量目标，不是截止线/虚假 KPI
- **全量线索库**：第一轮可向 100–200 条**具体事件/设定/玩法线索**扩展，随后继续追加；这是扩大覆盖的探索量级，不是硬性达标、不限制上限。
- **实际核验层**：力争 30–50 条有具体章节或可靠可定位证据的候选；搜不到应呈报真实证据限制，禁止用简介和 GPT 臆测凑数。
- **精读层**：只对有潜力的多个片段及连续前后因果深读，数量由证据质量而定，可跨批。
- **作者候选层**：可滚动累积 15–30 或更多不同的优质事件/玩法方向；每批提供一页易读精选+完整索引，而不是只交 5–7 个就 STOP。

这些数字是让执行者理解研究**应该足够广**，不是达到某个数字就停止，更不能以凑数字取代精选。

## 搜索多维度
1. 番茄男频优先，但不限热门书、不限新人、不限大类、不限一年期。
2. 起点/其他读者群接近的网文、历史经典与冷门高质量脑洞可入库，标明是否与番茄商业市场直接相关。
3. 作品线索、章节讨论、书评、读者自发复述、作者访谈等可作为检索起点；不能把未经核验的二手描述冒充读过正文。
4. 三个检索颗粒度：**核心高概念设定 / 单次具体神级事件 / 能在长篇里反复变出不同玩法的连续引擎**。
5. 不局限搞笑：意外、荒诞、爆笑、扮猪吃虎、社会性误解、利益链升级、极限反转、打破世界规律、悬念惊奇等，只看有无真正的读者吸引力与现实作品依据。
6. 反向搜索同一套路的失败/普通场面，以发现为什么特定版本不有效；不强制平均配比。

## 让“多”不退化为低质量清单
可计入 100–200 线索库的一条必须至少含：
- 独立的具体想法或场面（不能只写书名/题材）；
- 来源、可回查链接、检索时间；
- 一句能复述的具体内容；
- 证据状态（已读 / 可定位间接信息 / 待核验）；
- 去重键，避免同一桥段反复算作新条目。

结果分 **RAW DISCOVERED / SOURCE LOCATED / SCENE VERIFIED / CONTEXT READ / AUTHOR SELECTED / REJECTED**；绝不能把“搜到传闻”当“验证了神桥段”。

## 分批工作与停止
- 分批搜与分批入库，每轮继续扩充新的作品、类型与事件机制；上一批的高质量积累永久保留。
- 定期给作者精选、可追溯的不同类型候选，不需要做完所有搜索才开始展示。
- 当已有足够广的证据底盘，重复检索开始大量重复且**新增高价值场面明显变少**，记录覆盖与缺口，交作者决定继续拓展/改搜索方向/进入 B02。
- **不得因为拿到 5–7 条“感觉不错”的线索、或完成固定 8–12 本书就自动 STOP**。
- 不得无期限空转，分批报告投入产出与最具价值的新发现，让作者知道是否值得继续搜。
- B02 创作、新的正式首章仍须 AUTHOR GATE，方法B的版权和原创边界不变。
